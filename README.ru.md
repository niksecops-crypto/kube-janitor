# Kube-Janitor: Автоматизированная очистка ресурсов Kubernetes

Kube-Janitor — это легкая и эффективная утилита для очистки старых или неиспользуемых ресурсов в вашем кластере Kubernetes. Создана для DevOps-инженеров, которые хотят поддерживать порядок в своих кластерах и уменьшить фрагментацию ресурсов.

## Основные возможности

- **Автоматическая очистка подов**: Удаляет завершенные (Succeeded/Failed) поды, которые старше заданного порога времени.
- **Автоматическая очистка джобов**: Очищает завершенные или неудачные пакетные задания (Batch Jobs) и связанные с ними поды.
- **Режим Dry-run**: Предварительный просмотр удалений перед их фактическим выполнением, чтобы избежать случайной потери данных.
- **Настраиваемые пороги**: Установите, как долго хранить завершенные ресурсы.
- **Поддержка In-Cluster и Out-of-Cluster**: Работает как внутри вашего кластера, так и в качестве автономного CLI-инструмента.

## Почему Kube-Janitor?

Kubernetes не всегда немедленно очищает завершенные поды и джобы, что приводит к появлению тысяч "зависших" ресурсов, которые загромождают `kubectl get pods` и создают дополнительную нагрузку на API-сервер. Kube-Janitor автоматизирует эту рутинную работу.

## С чего начать?

### Требования

- Кластер Kubernetes (1.20+)
- Go 1.22+ (для сборки из исходного кода)
- `kubectl`, настроенный на ваш кластер

### Быстрый старт (Локально)

```bash
# Клонируйте репозиторий
git clone https://github.com/niksecops-crypto/kube-janitor.git
cd kube-janitor

# Сборка и запуск с порогом очистки 24 часа в режиме dry-run
go run cmd/janitor/main.go --max-age=24h --dry-run=true
```

### Развертывание в Kubernetes (Helm)

Мы предоставляем Helm-чарт для простого развертывания в качестве фоновой службы.

```bash
helm upgrade --install kube-janitor deploy/helm/kube-janitor \
  --namespace kube-system \
  --set maxAge=48h \
  --set dryRun=false
```

## Конфигурация

| Параметр | Описание | По умолчанию |
|-----------|-------------|---------|
| `--max-age` | Максимальный возраст завершенных ресурсов перед удалением | `24h` |
| `--dry-run` | Если true, не выполнять фактическое удаление | `false` |
| `--interval`| Как часто запускать цикл очистки | `1h` |
| `--kubeconfig` | Путь к kubeconfig (если запуск вне кластера) | In-cluster config |

## Лучшие практики для продакшена

- Всегда запускайте в режиме `dry-run` сначала, чтобы убедиться, какие ресурсы будут удалены.
- Установите подходящий `max-age` (например, `48h` или `72h`), чтобы иметь возможность вручную изучить логи упавших подов.
- Запускайте в выделенном неймспейсе с соответствующими RBAC правами.
